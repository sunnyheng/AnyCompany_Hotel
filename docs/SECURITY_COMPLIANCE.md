# Security & Compliance Notes

This document records the security posture of the reference implementation, the
decisions behind it, and every risk we consciously accepted (with the reason and
the production-hardening path). It is the companion to scan results (ProtoShield /
ASH for code, Holmes for docs): findings that are not fixed are explained here.

## Posture summary

| Area | Position |
| --- | --- |
| Network exposure | Serverless only. The reachable endpoints are Amazon Cognito's managed API, one API Gateway HTTP API protected by a Cognito JWT authorizer, and one CloudFront distribution serving the static demo UI. No EC2, no security groups, no open ports. |
| Static assets | The demo UI lives in a single S3 bucket with **all four Block Public Access settings enabled**, default encryption (SSE-S3) and an enforce-SSL bucket policy; it is readable only by the CloudFront distribution via Origin Access Control (sigv4, `AWS:SourceArn` condition). Viewers are redirected to HTTPS. |
| Data at rest | DynamoDB table encrypted with an AWS-managed KMS key. No PII beyond the seeded demo user's email; bookings are synthetic demo data. |
| Data in transit | TLS everywhere (Cognito, API Gateway, DynamoDB endpoints). |
| Identity | All API access requires a valid user-pool JWT; high-value writes additionally require a second, fresh JWT obtained through the OTP challenge (step-up). |
| IAM | Function roles are generated by CDK grants narrowed to `dynamodb:PutItem` + `dynamodb:Query` on the single table; SES send (when enabled) is scoped to the one sender identity ARN. |
| Secrets | None stored. OTPs are ephemeral (Cognito challenge session), never persisted, compared in constant time. |
| Auth hygiene | Password policy 12+ chars with all character classes; `preventUserExistenceErrors` enabled; self sign-up disabled; OTP limited to 3 attempts per session. |

## Accepted risks (and why)

### R-1 — Demo OTP fallback logs the code to CloudWatch Logs

`CreateAuthChallenge` falls back to `console.log` of the OTP when no
`SES_FROM_ADDRESS` is configured, because a fresh evaluation account has no
verified SES identity and the flow must still be demonstrable.
**Why accepted:** demo-only path, clearly marked in code; CloudWatch access in the
demo account already implies far stronger privileges than one OTP grants.
**Production path:** always deploy with `-c sesFromAddress=...` (the code then
never logs the OTP), or swap in SNS/SES with a dedicated identity. Tracked in
`docs/NEXT_STEPS.md`.

### R-2 — `USER_PASSWORD_AUTH` instead of SRP for primary sign-in

The SPA sends the password over TLS instead of doing an SRP exchange.
**Why accepted:** this is a *reference for the step-up pattern*; SRP adds a
client-library dependency and obscures the part we are demonstrating. TLS
protects the credential in transit.
**Production path:** AnyCompany's real sign-in is the Cognito Hosted UI /
managed login, which uses SRP; the step-up pattern is unchanged (see
`docs/PORTING_GUIDE.md`).

### R-3 — Lambda execution roles include the CloudWatch Logs wildcard-ish policy

CDK attaches `AWSLambdaBasicExecutionRole`-equivalent permissions whose log-group
resource is scoped to the function's own log group, but scanners sometimes flag
the managed-policy pattern.
**Why accepted:** this is the AWS-recommended baseline for Lambda logging; the
scope is the function's own log group.

### R-4 — No WAF / additional throttling in front of the HTTP API

**Why accepted:** the API is JWT-protected and the write path is additionally
step-up-protected; API Gateway default account-level throttling applies. A WAF
adds cost and configuration surface that distracts from the reference.
**Production path:** attach AWS WAF and per-route throttling before portfolio
rollout (`docs/NEXT_STEPS.md`).

### R-5 — Demo lifecycle settings: `RemovalPolicy.DESTROY`, no PITR

The user pool and table are destroyed with the stack and the table has
point-in-time recovery disabled.
**Why accepted:** evaluation accounts must be able to tear down cleanly;
the data is synthetic.
**Production path:** `RETAIN` + PITR + deletion protection on real pools/tables.

### R-6 — Cognito threat protection (advanced security) not enabled

Adaptive authentication / compromised-credentials detection is a paid feature
tier and unnecessary for a synthetic-data reference.
**Production path:** enable the Plus feature plan on the production pool; it
composes cleanly with custom auth challenges.

### R-7 — CORS allows the CloudFront origin plus one configurable dev origin

The API allows exactly two origins: the stack's own CloudFront distribution
(where the demo UI is hosted) and a deploy-time context parameter
(`-c webOrigin=...`, default `http://localhost:5173`) for local development.
**Why accepted:** never `*`; both origins are known and controlled.
**Production path:** drop the localhost origin.

### R-8 — Demo UI is publicly reachable on the default CloudFront domain

Anyone with the URL can load the static assets (HTML/JS/CSS). The bundle
contains the Cognito user pool / app client IDs and the API URL — all values
that are public by design in any SPA — and no secrets. Every API call still
requires a valid user-pool JWT, self sign-up is disabled, and high-value writes
require step-up.
**Why accepted:** a customer-facing demo must be reachable without local
tooling; the S3 origin itself remains fully private (Block Public Access +
OAC-only reads).
**Production path:** custom domain + ACM certificate, AWS WAF on the
distribution, and (if the audience must be restricted) CloudFront signed
cookies or an IP allowlist via WAF.

## Alignment with organizational AWS baselines

- **No storage service is publicly exposed** — the single S3 bucket has all
  four Block Public Access settings enabled and is readable only by CloudFront
  via Origin Access Control; DynamoDB is reachable only via IAM from the
  booking Lambda.
- **Web traffic enters through CloudFront** — never directly against storage
  or compute.
- **No ports are opened** — no security groups exist in the stack.
- **No EC2 / SSH / RDP surface** — compute is Lambda only.
